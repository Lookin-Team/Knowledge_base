# Предложка — локальная реализация 03.11.2026

Функциональность реализована через тему lookin-base, ядро и роли не изменены.
Локальное приложение запущено, таблица заявок создана. На VPS не установлено.

## Что доступно

«Предложить публикацию»: тип (новость, инструкция, другое), заголовок, обычный текст,
желаемая полка или направление, хэштеги. Без полки направление обязательно.
Текст до 15 000 символов, до 20 хэштегов. Добавлены картинки и документы: до 5 файлов по 2 МБ.
Сотрудник видит свои предложения и результат, чужие заявки ему недоступны.

Модератор открывает «Запросы на публикацию», редактирует, сохраняет правки,
выбирает книгу и публикует либо отклоняет с причиной. Полка — пожелание автора:
BookStack размещает страницы в книгах. Выбор главы пока не предусмотрен.
Все статусы в одной очереди, новые сверху, по 25 на страницу.

Исходная заявка сохраняется отдельно от правок, фиксируются ID автора, модератора,
время решения и ссылка на страницу. Ссылка показывается при наличии права чтения.
Публикация идёт от текущего модератора, с проверкой его штатных прав на книгу.
Повторное решение возвращает 409, строка заявки блокируется внутри транзакции.
Содержимое выводится безопасно, хэштеги становятся штатными тегами страницы.
Новость — тип заявки; демонстрационная лента главной автоматически не наполняется.

## Доступ и установка

Все команды выполнять из bookstack-local, только с compose.local.yaml.

1. Включить APP_THEME=lookin-base. Передавать через Git все файлы темы вместе:
   functions.php, proposals/, подключения меню home/default и lookin/sidebar.
2. Создать таблицу явно:
   `docker compose -f compose.local.yaml exec -T app php scripts/install-proposals.php`.
   Повторный запуск сохраняет существующие заявки, роли не меняет.
3. В защищённой .env задать LOOKIN_PROPOSAL_AUTHOR_IDS и
   LOOKIN_PROPOSAL_MODERATOR_IDS — числовые ID через запятую. Пусто = доступ закрыт.
   Не добавлять гостей, технических пользователей или ботов автоматически.
   Локально модератор — тестовый администратор №1. Список сотрудников пуст:
   локальных человеческих аккаунтов коллег нет. Тестовый ИИ-читатель не включён.
4. Применить настройки:
   `docker compose -f compose.local.yaml up -d app web`.
5. После локального входа открыть http://127.0.0.1:8080/publication-proposals/new.
   Очередь: /publication-proposals?queue=1. Для подключения сотрудника добавить
   его ID в список авторов, сохраняя его текущие роли и разрешения.

Остановка: `docker compose -f compose.local.yaml stop app web`.
Отдельных токенов или новых зависимостей не требуется. Маршруты используют
штатную сессию, проверку входа, CSRF и ограничения частоты (10 отправок в минуту).
Внутренние классы BookStack требуют повторной проверки при обновлении.

## Бэкап и откат

Включать lookin_publication_proposals в полный дамп БД, списки доступа сохранять
в защищённой конфигурации отдельно от Git. Локальную БД поверх VPS не переносить.
На сервере таблицу создавать только после согласованного бэкапа и поручения на установку.
Откат: закрыть списки доступа и убрать маршруты/подключения меню предложки,
сохранив таблицу и заявки. Восстановление бэкапа с новой таблицей ещё не проверено.

## Проверено

- PHPUnit: 6 тестов (включая файлы) — PASS на отдельной mysql_testing/bookstack-test.
- Отправка читателем, запрет чужого ID и модерации сотрудником, закрытый список
  доступа, скрытая полка, запрет публикации без штатного права на книгу.
- Правки, сохранение оригинала, отклонение с причиной, теги, безопасный вывод
  script-текста и защита от повторного решения (409).
- Реальный локальный HTTP: вход администратора, форма, личный список, очередь — PASS;
  POST без CSRF — 419. local-dev/proposal-http-check.py не печатает секреты.
- Повтор тестов:
  `docker compose -f compose.local.yaml exec -T app php vendor/bin/phpunit -c local-dev/phpunit-proposals.xml local-dev/tests/ProposalsTest.php`.
  Тестовая база подготовлена штатными миграциями и DummyContentSeeder.
- Git diff --check — PASS; upstream-файлы не менялись.

Не проверены: визуальное отображение на телефоне, параллельные запросы публикации,
нагрузка, восстановление и работа на VPS. Повторное решение проверено последовательными
запросами. Известные предупреждения среды см. SECURITY.ru.md; предложка их не устраняет.


## Картинки и документы (03.11.2026)

В форме появилась загрузка JPG/PNG/WebP/GIF, PDF, Word, Excel, PowerPoint,
TXT и CSV. До пяти файлов по 2 МБ каждый. Проверяются размер, количество,
содержимое и расширение. Для современных Office-файлов проверяется структура
контейнера без распаковки. HTML, SVG, скрипты и архивы не принимаются.
Проверка формата не является антивирусной проверкой; антивирус не подключён.

Исходные файлы сохраняются в закрытой таблице lookin_proposal_files (base64),
вместе с заявкой в одной транзакции. Это небольшой локальный вариант хранения:
размер БД и дампов увеличивается примерно на треть от объёма файлов.
Публичных файлов до публикации нет. Скачать может только автор или модератор
через маршрут с проверкой доступа на каждом запросе. Картинки имеют предпросмотр;
документы выдаются скачиванием с nosniff. Отклонение не удаляет исходные файлы.

При рассмотрении можно снять отметки с файлов, которые не следует публиковать.
Выбранные файлы становятся обычными вложениями статьи через AttachmentService,
с проверкой прав модератора на вложения и изменение статьи. Картинки в статье
пока также являются вложениями, автоматически в текст не вставляются.
Оригиналы заявки сохраняются закрытыми. Чужой ID файла/заявки недоступен.
После ошибки формы браузер требует выбрать файлы заново.

Обновление существующей установки: повторно выполнить scripts/install-proposals.php,
он добавит только отсутствующую таблицу файлов и сохранит заявки. Затем обновить
тему целиком. В полный бэкап включать обе таблицы предложки и штатное хранилище
вложений BookStack. Восстановление этого набора ещё не проверено.

Тестами проверены загрузка картинки/документа, точное содержимое скачивания,
приватный предпросмотр, запрет доступа чужому автору, выбор части вложений,
перенос в статью, права чтения статьи, запрет повторной публикации, поддельная
картинка, запрещённые типы, превышение размера и числа файлов. Форма загрузки
проверена в открытой вкладке браузера. Набор реальных Office-файлов отдельно
не прогонялся; проверки форматов используют MIME и структуру контейнера.
